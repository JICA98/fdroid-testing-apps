## Notes

- Review on OnePlus 13 (API 36). Gallery restore flow verified end-to-end: system photo picker, editor (Gamma/Contrast/Brightness/Warmth sliders), crop mode with Apply/Reset and rotation (0 to 90 deg), save to gallery ("Photo saved to gallery"; FilmFlip_*.jpg verified in /sdcard/Pictures/). Backlight feature (white screen for illuminating film, "Place film against the screen") works.
- BUG - camera flow broken: the manifest declares CAMERA but the app never requests it at runtime (no requestPermissions/checkSelfPermission anywhere in the source; no prompt shown on device). Tapping the capture button fails silently with a permission denial (logcat: "Permission Denial: can't use the camera pid=... uid=..."). The user would have to manually grant CAMERA in app settings, and the app shows no error or guidance when it fails. "Shoot with Camera" is a main described function, hence functions_ok: false.
- The app never demands any runtime permission at startup - it can be fully used (gallery flow) without granting anything.
- Package name "com.example.filmflip" is a template-style application ID; the MR title ("New App: com.example.filmflip") and description still contain the fdroiddata template boilerplate ("Please remove above lines!") - worth cleaning up before merge.
- No INTERNET permission in the manifest; network capture not applicable. No MANAGE_EXTERNAL_STORAGE.
- Custom adaptive icon (custom background/foreground, monochrome layer). MIT license; category Camera per metadata; English UI.
- VirusTotal: 0 malicious / 0 suspicious / 66 undetected.
