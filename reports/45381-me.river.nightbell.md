## Notes

- Full review pass completed on OnePlus 13 (API 36): onboarding, monitor creation wizard (status check, expectations, cadence, alerts), scheduled + manual checks, down-detection with alert notification (Re-check now / Mute 1h actions), monitor detail (TLS cert, history, delete), Settings (alert policy, sounds, haptics, reference endpoint).
- All network traffic captured with PCAPdroid (targeted app filter). Only two destinations observed: the monitored site itself (example.com -> Cloudflare 104.20.23.154) and https://www.gstatic.com/generate_204 (Google).
- The gstatic connection is the app's latency-reference probe (latency budget / "slow" alerts). It is probed at app launch and during checks, is user-configurable in Settings ("Reference endpoint"), and degrades gracefully if blocked ("latency is judged raw - nothing breaks"). Not tracking; no update check observed; no other third-party endpoints in source.
- POST_NOTIFICATIONS is requested in the first-launch onboarding but is skippable; the app was fully usable without granting it (all flows above tested with notifications denied). Notifications are the app's core function (alerting), so this is justifiable.
- Special-access permissions (REQUEST_IGNORE_BATTERY_OPTIMIZATIONS, ACCESS_NOTIFICATION_POLICY, USE_FULL_SCREEN_INTENT) are explained in-app in the onboarding and granted only via system settings; skippable.
- The element-monitor feature uses a WebView to load the target page for element selection - core functionality, not a decorative in-app webview.
- Custom bell vector icon (not the default icon). Apache-2.0, category System per metadata; no accounts, no server, no analytics (source-verified).
- VirusTotal: 0 malicious / 0 suspicious / 67 undetected.
