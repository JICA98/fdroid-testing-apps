## Notes

- Full review pass on OnePlus 13 (API 36): feed (Top/New/Best/Ask/Show tabs), story list, article reader with full extracted text, article search with filters (Relevant/Newest, All/Stories/Ask HN), category chips. All worked without crashes; feed content visibly loaded over the network (fresh install).
- IMPORTANT - capture caveat: PCAPdroid packet capture could not be completed reliably on this device: the intent-based capture did not apply the app filter (control-request confirmation dialog interfered, dumps came back unfiltered and contaminated with unrelated/ICMP traffic). Network conclusions below therefore come from source-code review and the project's PRIVACY.md, which are precise and explicit, rather than from a clean packet capture.
- Per source + PRIVACY.md, Kiosk connects only to: the official read-only Hacker News API (hacker-news.firebaseio.com) for feed/story/comment data; the unauthenticated Algolia HN Search API (hn.algolia.com) for search; article pages and favicons/images from story source domains (fetched for the reader - the reader is a WebView used to extract article content, which is the app's core function, not a decorative webview). External links open in the system browser only on user action.
- No update check, no tracking/analytics/ad SDKs, no Firebase SDK, no Play Services, no accounts (PRIVACY.md). AntiFeatures TetheredNet correctly declared in the MR metadata (HN API + Algolia).
- No runtime (dangerous) permissions at all; permission set is just INTERNET + ACCESS_NETWORK_STATE - minimal for a feed reader. No MANAGE_EXTERNAL_STORAGE.
- Custom adaptive icon (orange + custom foreground, monochrome layer). Apache-2.0; categories Internet/Reading per metadata. English UI.
- VirusTotal: 0 malicious / 0 suspicious / 67 undetected.
