## Notes

- Full review pass on OnePlus 13 (API 36): feed (Top/New/Best/Ask/Show tabs), story list, article reader with full extracted text, article search with filters (Relevant/Newest, All/Stories/Ask HN), category chips. All worked without crashes.
- Network capture completed successfully on the second attempt (PCAPdroid, target app = Kiosk, verified via the connections log): destinations observed were only hacker-news.firebaseio.com (official HN API - feed/story data, multiple HTTPS connections), hn.algolia.com (HN search API - confirmed when performing a search), and the article source domains from the feed (www.theguardian.com, www.abc.net.au, jonty.github.io, aresluna.org, thenextweb.com, owlposting.com, blogs.embarcadero.com, s0.wp.com = WordPress CDN for favicons/images). Exactly matches the project's PRIVACY.md and source code.
- No tracking, no analytics, no update-check, no other third-party endpoints observed. Feed data fetched at app start (conn_on_start = HN feed load, which is the app's core function).
- The article reader uses a WebView to extract article content (core feature, documented in PRIVACY.md as "Article pages selected or warmed for reader extraction"); external links open in the system browser only on user action.
- No runtime (dangerous) permissions at all; permission set is just INTERNET + ACCESS_NETWORK_STATE. No MANAGE_EXTERNAL_STORAGE. AntiFeatures TetheredNet correctly declared in the MR metadata.
- Custom adaptive icon (orange + custom foreground, monochrome layer). Apache-2.0; categories Internet/Reading per metadata. English UI.
- VirusTotal: 0 malicious / 0 suspicious / 67 undetected.
